# 🧠 哲学原则

结论：AgentPlane 的哲学原则采用三层架构，以求是 skills 作为底座。优先级为具体原则 > 方法论 > 哲学基座。

---

## 🧠 三层架构

```
┌─────────────────────────────────────────┐
│           具体原则（工程原则）            │
│   YAGNI / DRY / KISS / SOLID            │
│   CLI-first / 投影模型 / 执行闭环       │
│   Skill 路由 / 安全护栏 / 人类在环       │
├─────────────────────────────────────────┤
│           方法论（工作方法）              │
│   调查研究 / 群众路线 / 批评与自我批评   │
│   费曼学习法 / 苏格拉底式提问           │
├─────────────────────────────────────────┤
│           哲学基座（认识论）              │
│   实事求是 / 矛盾分析法 / 实践认识论     │
│   第一性原理 / 奥卡姆剃刀               │
└─────────────────────────────────────────┘
```

---

## 🔬 哲学基座

| 原则 | 核心要义 | 应用场景 |
|------|----------|----------|
| **实事求是** | 从客观存在的实际事物出发 | 所有决策和判断 |
| **矛盾分析法** | 识别并抓住主要矛盾 | 问题分析、优先级判断 |
| **实践认识论** | 实践→认识→再实践的螺旋上升 | 学习、改进、迭代 |
| **第一性原理** | 从最基本的事实出发，而不是类比 | 架构设计、技术选型 |
| **奥卡姆剃刀** | 如无必要，勿增实体 | 简化设计、减少复杂度 |

---

## 📖 方法论

| 原则 | 核心要义 | 应用场景 |
|------|----------|----------|
| **调查研究** | 先调查再发言 | 需求分析、问题诊断 |
| **群众路线** | 收集→系统化→返回→验证 | 用户调研、团队协作 |
| **批评与自我批评** | 惩前毖后，治病救人 | 代码审查、回顾改进 |
| **费曼学习法** | 用简单语言解释复杂概念 | 文档编写、知识传递 |
| **苏格拉底式提问** | 通过提问引导思考 | 需求分析、决策讨论 |

---

## 🛠️ 工程原则

| 原则 | 核心要义 | 应用场景 |
|------|----------|----------|
| **YAGNI** | 不要过度设计 | 功能设计、架构设计 |
| **DRY** | 不要重复代码 | 代码编写、重构 |
| **KISS** | 保持简单 | 设计、实现 |
| **SOLID** | 面向对象设计五原则 | 架构设计、代码编写 |
| **CLI-first** | 所有操作通过统一入口 | 命令设计、API 设计 |
| **投影模型** | 声明/证据/摘要三层分离 | 数据管理、状态管理 |
| **执行闭环** | Plan → Apply → Verify → Record | 操作流程、任务管理 |

---

## 📌 优先级

**具体原则 > 方法论 > 哲学基座**

当原则冲突时，遵循此优先级。具体原则直接影响代码和架构，方法论影响工作方式，哲学基座影响思维方式。
