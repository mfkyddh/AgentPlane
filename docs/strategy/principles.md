# 🧠 哲学原则

结论：AgentPlane 的哲学原则采用三层架构，以求是 skills 作为底座，集成其他哲学原则和工程原则。优先级为具体原则 > 方法论 > 哲学基座，通过检查清单和自动触发机制确保原则被遵循。

## 哲学基座（认识论）

### 求是哲学

**来源**：[qiushi-skill](https://github.com/HughYau/qiushi-skill)

| 原则 | 核心要义 | 来源 | 应用场景 |
|------|----------|------|----------|
| **实事求是** | 从客观存在的实际事物出发，让事实规定判断，让现实修正理论 | 总原则 | 所有决策和判断 |
| **矛盾分析法** | 识别并抓住主要矛盾 | 《矛盾论》 | 问题分析、优先级判断 |
| **实践认识论** | 实践→认识→再实践的螺旋上升 | 《实践论》 | 学习、改进、迭代 |

### 其他哲学

| 原则 | 核心要义 | 来源 | 应用场景 |
|------|----------|------|----------|
| **第一性原理** | 从最基本的事实出发，而不是类比 | 哲学传统 | 架构设计、技术选型 |
| **奥卡姆剃刀** | 如无必要，勿增实体 | 哲学传统 | 简化设计、减少复杂度 |

## 具体原则（工程原则）

### 软件工程原则

| 原则 | 核心要义 | 来源 | 应用场景 |
|------|----------|------|----------|
| **YAGNI** | 不要过度设计，只实现当前需要的功能 | 极限编程 | 功能设计、架构设计 |
| **DRY** | 不要重复代码，提取公共逻辑 | 极限编程 | 代码编写、重构 |
| **KISS** | 保持简单，避免复杂 | 美国海军 | 设计、实现 |
| **SOLID** | 单一职责、开闭原则、里氏替换、接口隔离、依赖反转 | 面向对象设计 | 架构设计、代码编写 |

### AgentPlane 特有原则

| 原则 | 核心要义 | 来源 | 应用场景 |
|------|----------|------|----------|
| **CLI-first** | 所有操作通过统一入口 | AgentPlane 设计 | 命令设计、API 设计 |
| **投影模型** | 声明/证据/摘要三层分离 | AgentPlane 设计 | 数据管理、状态管理 |
| **执行闭环** | Plan → Apply → Verify → Record | AgentPlane 设计 | 操作流程、任务管理 |
| **Skill 路由** | AI 意图到 CLI 的映射 | AgentPlane 设计 | Agent 设计、能力管理 |
| **安全护栏** | AI 必须遵守的规则 | AgentPlane 设计 | Agent 约束、安全控制 |
| **人类在环** | 关键决策需要人类确认 | AgentPlane 设计 | 审批流程、风险控制 |

## 优先级

**具体原则 > 方法论 > 哲学基座**

**含义**：
- **具体原则**最优先：确保执行正确
- **方法论**次之：确保工作方式正确
- **哲学基座**最后：确保方向正确

**理由**：
- 具体原则直接影响代码和架构
- 方法论影响工作方式
- 哲学基座影响思维方式

**应用**：
- 当原则冲突时，遵循优先级
- 具体原则优先于方法论
- 方法论优先于哲学基座

## 调用机制

### 求是原则：自动注入

**机制**：每次会话开始时，求是原则自动注入。

**来源**：[qiushi-skill](https://github.com/HughYau/qiushi-skill)

**包含原则**：
- 实事求是（总原则）
- 矛盾分析法
- 实践认识论
- 调查研究
- 群众路线
- 批评与自我批评
- 持久战略
- 集中兵力
- 星火燎原
- 统筹兼顾

### 其他原则：自动触发

**机制**：根据用户输入自动触发其他原则。

**判断方式**：根据用户输入内容判断场景。

**触发示例**：
- 用户说"帮我重构这段代码" → 触发 SOLID 原则
- 用户说"这个功能太复杂了" → 触发 KISS 原则
- 用户说"这里有重复代码" → 触发 DRY 原则
- 用户说"帮我设计这个功能" → 触发 YAGNI 原则
- 用户说"帮我写文档" → 触发费曼学习法
- 用户说"帮我分析问题" → 触发第一性原理
