# 决策记录：项目定位

## 状态

**接受**

## 日期

2026-04-30

## 背景

AgentPlane 项目经过多次重构，需要明确长期定位和战略方向。通过苏格拉底式提问和深入讨论，我们澄清了项目的核心概念和价值主张。

## 决策

### 1. 一句话愿景

**"给 Agent 的产品全生命周期控制面"**

**含义**：
- **Agent**：AI 代理，直接用英文
- **产品**：包含多个业务系统 + 全局配置
- **全生命周期**：从创建到运维的所有阶段
- **控制面**：决策层，不是执行层

### 2. 长期目标

**3 年内成为小团队的标准工具，拥有 100+ 用户**

### 3. 核心价值主张

**"Agent 安全管理产品全生命周期"**

### 4. 目标用户

**同时面向四种用户**：
- 个人开发者
- 小团队（2-10 人）
- 开源维护者
- 自托管服务维护者

**共同特点**：
- 资源有限
- 需要自动化
- 需要安全可控
- 需要可追溯

### 5. 成功标准

**用户满意度**

**含义**：
- 不依赖外部指标（用户数、活跃度、影响力）
- 依赖内在感受（功能实现、用户体验、项目质量）
- 主观判断，而非客观数据

### 6. 项目定义

**项目**：产品线级别，包含多个业务系统 + 全局配置

**层级设计**：项目 → 业务系统 → 应用

**配置管理**：应用通过配置文件（如 `config.yaml`）声明配置

**操作粒度**：业务开发由人类做，运维由 AgentPlane 管

### 7. 非目标

**不替代现有工具**：
- Terraform（不管云资源全生命周期）
- Kubernetes（不做容器编排）
- Ansible（不做配置编排）
- CI/CD 工具（不做持续集成/持续部署）
- 监控工具（不做实时监控）

**不服务的场景**：
- 大型企业（不支持大型多租户平台）
- 强一致场景（不支持强一致持续调谐）
- 实时系统（不支持实时系统）

**不成为的形态**：
- SaaS（不做托管服务）
- 通用 Agent 框架（不做通用 Agent 框架）
- 大型 DevOps 平台（不做大型 DevOps 平台）

**不管的内容**：
- 业务开发（不管代码编写、代码审查、单元测试）
- 代码编辑（不做代码编辑器）
- 版本控制（不做版本控制系统）

## 理由

### 为什么选择这个定位？

1. **聚焦核心价值**：专注于 Agent 和产品全生命周期，避免范围过大
2. **明确目标用户**：同时面向四种用户，但共同特点是资源有限、需要自动化
3. **内在成功标准**：用户满意度，而非外部指标，更符合项目本质
4. **清晰边界**：明确不做什么，避免资源分散

### 为什么不是其他定位？

**为什么不是"通用 Agent 框架"？**
- 范围太大，无法聚焦
- 需要更多资源和时间
- 不符合当前阶段

**为什么不是"大型 DevOps 平台"？**
- 目标用户是小团队和个人开发者
- 复杂度太高，不适合当前阶段
- 不符合"简单"的原则

**为什么不是"SaaS"？**
- 当前阶段需要专注核心功能
- 需要更多资源和基础设施
- 不符合"可 fork"的设计理念

## 替代方案

### 方案 A：通用 Agent 框架

**描述**：成为通用的 Agent 框架，支持各种场景

**优点**：
- 范围广，用户多
- 可扩展性强

**缺点**：
- 范围太大，无法聚焦
- 需要更多资源和时间
- 不符合当前阶段

### 方案 B：大型 DevOps 平台

**描述**：成为大型的 DevOps 平台，支持企业级场景

**优点**：
- 市场大，价值高
- 可商业化

**缺点**：
- 目标用户不匹配
- 复杂度太高
- 不符合"简单"的原则

### 方案 C：SaaS 服务

**描述**：成为托管的 SaaS 服务

**优点**：
- 用户体验好
- 可商业化

**缺点**：
- 需要更多资源和基础设施
- 不符合"可 fork"的设计理念
- 不符合当前阶段

## 影响

### 对产品设计的影响

1. **聚焦核心功能**：专注于 Agent 和产品全生命周期
2. **简化用户界面**：面向小团队和个人开发者，需要简单易用
3. **清晰边界**：明确不做什么，避免功能蔓延

### 对技术架构的影响

1. **可扩展性**：支持项目 → 业务系统 → 应用三层结构
2. **配置管理**：支持应用通过配置文件声明配置
3. **操作粒度**：支持业务开发由人类做，运维由 AgentPlane 管

### 对文档体系的影响

1. **战略文档**：建立愿景、原则、路线图、决策记录
2. **用户文档**：面向目标用户，简单易懂
3. **技术文档**：面向开发者，清晰准确
