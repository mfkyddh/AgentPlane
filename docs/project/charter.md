# 📜 项目章程

结论：AgentPlane 的项目章程定义了项目的目标、范围、约束和假设，是项目层的核心文档。

---

## 项目概述

**项目名称**：AgentPlane

**一句话定位**：给 Agent 的产品全生命周期控制面

**项目类型**：开源 CLI 工具

**当前阶段**：Alpha

---

## 项目目标

### 长期目标

**3 年内成为小团队的标准工具，拥有 100+ 用户**

### 阶段目标

| 阶段 | 目标 | 退出标准 |
|------|------|----------|
| **Alpha**（当前） | 夯实核心 | 所有核心 Skill 有完整测试、文档体系覆盖目标场景、至少一个真实应用完成全生命周期验证 |
| **Beta** | 开放验证 | 至少 10 个外部用户成功使用、Provider 合同稳定、App delivery schema 正式发布 |
| **GA** | 规模扩展 | 100+ 活跃用户、社区自运转、至少 3 个成功案例文档化 |

### 成功标准

**用户满意度**（主观判断，而非客观数据）

- 你自己对项目功能实现的满意度
- 用户对项目体验的满意度
- 项目本身的质量和完整性

---

## 项目范围

### 做什么

| 功能领域 | 说明 |
|----------|------|
| **CLI 入口** | 所有正式操作通过 `agentplane <domain> <surface> <verb> [flags]` |
| **执行闭环** | Plan → Apply → Verify → Record 生命周期 |
| **投影模型** | Host Inventory → Object Ledgers → App Summaries |
| **Skill 路由** | AI 意图到 CLI 命令的映射 |
| **跨平台执行** | Windows、WSL、Linux 支持 |

### 不做什么

| 非目标 | 理由 |
|--------|------|
| 替代 Terraform | 范围太大，不是 AgentPlane 的定位 |
| 替代 Kubernetes | 复杂度太高，不是 AgentPlane 的目标 |
| 替代 Ansible | 偏 Agent 任务入口和证据，不偏配置执行 |
| 成为 SaaS | 当前阶段不适合，需要专注核心功能 |
| 成为通用 Agent 框架 | 专注于产品生命周期管理 |

## 约束条件

### 资源约束

| 资源 | 约束 |
|------|------|
| **维护者** | 单人维护（当前） |
| **时间** | 业余时间投入 |
| **资金** | 无商业收入 |

### 技术约束

| 约束 | 说明 |
|------|------|
| **Python 3.12+** | 唯一运行时 |
| **PyYAML>=6.0** | 唯一运行时依赖 |
| **uv** | 包管理器 |
| **Ruff** | 代码风格和格式化 |

### 设计约束

| 约束 | 说明 |
|------|------|
| **CLI-first** | 所有操作通过统一入口 |
| **Agent-first** | AI 友好设计 |
| **可 fork** | 用户可以 fork 后定制 |
| **离线优先** | 默认测试设计为确定性和离线 |

## 假设与依赖

### 假设

| 假设 | 风险 | 应对 |
|------|------|------|
| 小团队需要 AI 辅助运维 | 市场需求不足 | 通过真实用户验证 |
| CLI-first 是正确的技术选择 | 用户不习惯 CLI | 提供文档和教程 |
| 开源模式可持续 | 维护者 burnout | 建立社区，分散维护 |

### 依赖

| 依赖 | 说明 | 风险 |
|------|------|------|
| Python 生态 | 运行时和工具链 | 低风险 |
| GitHub | 代码托管、CI/CD | 低风险 |
| 1Panel | 当前主要 Provider | 中风险（Provider 合同待稳定） |
| WSL | Windows 开发环境 | 低风险 |
