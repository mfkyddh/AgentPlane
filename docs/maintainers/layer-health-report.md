# AgentPlane 四层体系健康度报告

结论：本文定义 AgentPlane 四层体系（战略、项目、工程、技术）的健康度指标和报告机制。每层有明确的量化指标和主观评估维度，通过定期报告跟踪项目整体健康状态。下次人类引用本文并说"生成健康报告"时，Agent 必须按本文模板收集指标、评估状态、生成报告。

## 用途

本文只定义健康度指标框架和报告模板，不替代：

| 不替代 | 真源 |
| --- | --- |
| 战略蓝图 | [agentplane-ultimate-blueprint.md](../reference/agentplane-ultimate-blueprint.md) |
| 路线图推进 | [agentplane-roadmap-workbook.md](agentplane-roadmap-workbook.md) |
| 架构契约 | [control-plane.md](../architecture/control-plane.md) |
| 仓库状态 | `agentplane repo status --repo-root .` |

## 四层体系定义

| 层级 | 名称 | 关注点 | 核心问题 |
| --- | --- | --- | --- |
| L1 | 战略层 (Strategy) | 愿景、原则、路线图、决策记录 | 我们在做正确的事吗？ |
| L2 | 项目层 (Project) | 项目章程、角色、沟通、风险 | 我们在正确地做事吗？ |
| L3 | 工程层 (Engineering) | 代码风格、Git 规范、测试、发布 | 我们的做事方式可持续吗？ |
| L4 | 技术层 (Technical) | 架构、规范、运维 | 我们的技术基础稳固吗？ |

## 健康度指标

### L1 战略层指标

| 指标 | 定义 | 目标 | 数据来源 | 评估方式 |
| --- | --- | --- | --- | --- |
| 决策记录数 | 已归档的 ADR 数量 | 每季度至少 1 个 | `docs/strategy/decisions/` 目录文件数 | 定量 |
| 路线图更新频率 | 路线图最近更新距今天数 | 每季度检查（≤90 天） | `ROADMAP.md` git log | 定量 |
| 原则遵循度 | 战略文档与实际执行的一致性 | 主观评估 ≥4 分 | 人工审查 | 主观 |

**评分标准（1-5 分）**：

| 分数 | 决策记录数 | 路线图更新频率 | 原则遵循度 |
| --- | --- | --- | --- |
| 5 | ≥4 个/年 | ≤30 天 | 完全一致，无偏离 |
| 4 | 3 个/年 | ≤60 天 | 基本一致，偶有偏离已修正 |
| 3 | 2 个/年 | ≤90 天 | 部分一致，存在已知偏离 |
| 2 | 1 个/年 | ≤180 天 | 多处偏离，尚未修正 |
| 1 | 0 个 | >180 天 | 严重偏离，原则形同虚设 |

## 附录

### 数据收集命令

```bash
# L1 战略层
ls docs/strategy/decisions/ | wc -l  # 决策记录数
git log -1 --format=%ci ROADMAP.md   # 路线图最后更新

# L2 项目层
ls docs/architecture/control-plane.md docs/reference/repository-structure.md docs/reference/git-conventions.md docs/reference/testing-architecture.md 2>/dev/null | wc -l  # 核心文档数

# L3 工程层
uv run python -m pytest --tb=short 2>&1 | tail -1  # 测试结果
agentplane repo health-check --repo-root . 2>&1 | grep -c "error"  # 文档门禁
uv run ruff check . 2>&1 | wc -l  # 代码风格警告数

# L4 技术层
ls docs/strategy/decisions/ | grep -i "technical\|arch" | wc -l  # 技术 ADR 数
```

### 评分计算方法

综合评分 = (L1 + L2 + L3 + L4) / 4

趋势判断：
- 上升：本次综合评分 > 上次综合评分
- 稳定：本次综合评分 = 上次综合评分
- 下降：本次综合评分 < 上次综合评分
```

## 报告生成协议

当人类引用本文并说"生成健康报告"时，Agent 必须按以下顺序执行：

1. **读取真源**：读取本文、[终极蓝图](../reference/agentplane-ultimate-blueprint.md)、[路线图工作簿](agentplane-roadmap-workbook.md)。
2. **收集定量指标**：运行"数据收集命令"中的命令，收集各层指标。
3. **评估主观指标**：基于文档审查和项目状态，评估主观维度。
4. **计算评分**：按评分标准计算各层分数和综合分数。
5. **判断趋势**：与上次报告对比，判断趋势方向。
6. **识别问题**：列出各层主要问题。
7. **提出建议**：针对问题提出改进建议。
8. **生成报告**：按模板格式生成完整报告。
9. **保存报告**：将报告保存到 `docs/maintainers/health-reports/YYYY-MM-DD.md`。

禁止行为：

1. 不读取真源就凭记忆生成报告。
2. 跳过定量指标收集，只做主观评估。
3. 不对比历史数据就判断趋势。
4. 只列问题不提建议。
5. 报告不保存到指定目录。

## 健康度阈值

| 综合评分 | 状态 | 含义 | 建议动作 |
| --- | --- | --- | --- |
| 4.5-5.0 | 优秀 | 项目健康，持续改进 | 保持当前节奏 |
| 3.5-4.4 | 良好 | 基本健康，有改进空间 | 关注未达标指标 |
| 2.5-3.4 | 一般 | 存在风险，需要干预 | 优先修复 P0 问题 |
| 1.5-2.4 | 警告 | 多处问题，需要紧急处理 | 暂停新功能，专注修复 |
| 1.0-1.4 | 危险 | 项目可能失败 | 需要全面审查和重组 |
