# 人机协作协议

结论：本文定义 AgentPlane 项目中人类与 AI Agent 的协作规则。人类只用自然语言表达需求，AI 负责全部实施工作（代码和文档）。AI 必须始终围绕主线推进，将随机输入收敛到主线中。

---

## 一句话原则

**人类表达意图，AI 自主推进，所有工作回归主线。**

---

## 协作模型

```
人类（意图层）               AI（执行层）
─────────────               ─────────────
  表达需求          ──→      意图解析
                            判断归属（主线/分支/backlog）
                   ←──      计划确认（如需）
  确认/调整         ──→      自主执行
                            自动验证
                   ←──      交付报告
  下一步指示        ──→      ...
```

---

## 主线机制

### 什么是主线

主线是当前阶段必须完成的工作，由三个条件定义：

1. 所有核心 Skill 有完整测试
2. 文档体系覆盖所有目标用户场景
3. 至少一个真实应用完成全生命周期验证

所有工作必须归属于以下三类之一：

| 类别 | 定义 | 处理方式 |
|------|------|----------|
| **主线** | 直接服务当前阶段目标 | 立即执行 |
| **分支** | 间接相关或临时需求 | 创建分支任务，完成后回归主线 |
| **backlog** | 有价值但当前不需要 | 记录，暂不执行 |

### 需求收敛规则

当人类提出新需求时，AI 的标准处理流程：

```
收到需求
  │
  ├── 判断：这个需求服务主线的哪个条件？
  │
  ├── 直接服务主线 → 合入主线，更新 backlog.md
  │
  ├── 间接相关 → 创建分支任务
  │   ├── 标注服务的主线条件
  │   ├── 预估工作量
  │   └── 定义回归主线的条件
  │
  └── 完全无关 → 记录到 backlog
      ├── 询问人类：现在做还是以后做？
      └── 如果现在做 → 转为分支任务
```

## 会话协议

### 会话开始

AI 在每次新会话开始时必须：

1. 读取 `docs/project/backlog.md`
2. 确认主线当前进度
3. 向人类报告：

> 上次我们在主线的 [具体位置]。当前进度：[条件一/二/三的状态]。继续推进主线，还是有新的需求？

### 会话进行中

#### 自主执行边界

AI 可以自主决定的事项：
- 代码实现的具体方式
- 文档的结构和措辞
- 测试用例的设计
- 提交的拆分方式
- 文件的组织方式

AI 必须请求确认的事项：
- 改变技术架构方向
- 修改或删除已有功能
- 改变项目的核心约束
- 涉及外部服务的操作（部署、推送等）
- 与主线方向不一致的需求

#### 分支任务处理

当人类提出偏离主线的需求时：

1. 不要拒绝，也不要盲目执行
2. 先评估这个需求能否收敛回主线
3. 如果可以收敛 → 告诉人类"这个可以归入主线的 [条件X]，因为 [理由]"
4. 如果不能收敛 → 创建分支任务，标注回归条件

### 会话结束

AI 在会话结束时必须：

1. 更新 `docs/project/backlog.md`：
   - 标记完成的任务
   - 更新进行中的任务状态
   - 记录新发现的问题
2. 如果有重要决策或发现，更新 memory
3. 告诉人类：本次完成了什么，下次应该从哪里开始

## 需求表达方式

### 人类不需要做的事

- 不需要指定文件路径
- 不需要写 commit message
- 不需要运行测试命令
- 不需要管理 git 操作
- 不需要记住主线进度

### 人类需要做的事

- 用自然语言表达需求
- 在 AI 请求确认时做出决定
- 在 AI 交付报告后给出反馈
- 告诉 AI 优先级（如果有多件事）

### 需求示例

| 人类说的 | AI 应该做的 |
|---------|------------|
| "帮我加个功能" | 先问清楚是什么功能，判断归属，再执行 |
| "这个 bug 怎么回事" | 调查原因，修复，判断是否需要回归主线 |
| "继续推进主线" | 读取 backlog.md，从上次停下的地方继续 |
| "先不管主线，我有个想法" | 记录想法，判断归属，决定是现在做还是放 backlog |
| "这些文档太乱了" | 评估哪些文档需要整理，制定计划，执行 |
