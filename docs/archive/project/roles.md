# 👥 角色与职责

结论：AgentPlane 定义了四种角色：维护者、贡献者、用户、AI Agent，每种角色有明确的职责和权限。

---

## 角色概览

```
┌─────────────────────────────────────────────────────────────┐
│                      维护者 (Maintainer)                     │
│                   项目所有者，最终决策者                      │
├─────────────────────────────────────────────────────────────┤
│                      贡献者 (Contributor)                    │
│                   外部开发者，提交 PR                         │
├─────────────────────────────────────────────────────────────┤
│                        用户 (User)                           │
│              使用 AgentPlane 的个人或团队                     │
├─────────────────────────────────────────────────────────────┤
│                      AI Agent                                │
│              通过 Skill 调用 CLI 的 AI                       │
└─────────────────────────────────────────────────────────────┘
```

---

## 维护者 (Maintainer)

**当前状态**：单人维护

### 职责

| 职责领域 | 具体内容 |
|----------|----------|
| **战略方向** | 定义愿景、路线图、重大决策 |
| **架构设计** | 核心架构、技术选型、架构决策 |
| **代码质量** | 代码审查、测试覆盖、文档完整性 |
| **发布管理** | 版本号、发布时机、发布流程 |
| **社区管理** | Issue 响应、PR 审查、用户支持 |
| **文档维护** | 文档更新、文档治理、术语统一 |

### 权限

| 权限 | 说明 |
|------|------|
| **代码合并** | 所有 PR 需要维护者审查和合并 |
| **发布决策** | 决定发布时间和版本号 |
| **架构决策** | 最终架构决策权 |
| **战略决策** | 最终战略决策权 |

### 时间投入

- **预期**：业余时间投入
- **风险**：维护者 burnout
- **应对**：建立社区，逐步分散维护

## 贡献者 (Contributor)

### 职责

| 职责领域 | 具体内容 |
|----------|----------|
| **代码贡献** | 提交 PR、修复 bug、添加功能 |
| **文档贡献** | 改进文档、添加教程、修复错误 |
| **测试贡献** | 添加测试、改进测试覆盖 |
| **问题报告** | 报告 bug、提出功能请求 |

### 权限

| 权限 | 说明 |
|------|------|
| **代码提交** | 可以 fork 仓库，提交 PR |
| **Issue 创建** | 可以创建 Issue |
| **讨论参与** | 可以参与 Discussion |

### 贡献流程

1. **Fork 仓库**
2. **创建分支**（遵循 Git 规范）
3. **提交代码**（遵循代码风格）
4. **创建 PR**（使用 PR 模板）
5. **等待审查**（维护者审查）
6. **合并代码**（维护者合并）

## 用户 (User)

### 用户类型

| 用户类型 | 特点 | 需求 |
|----------|------|------|
| **个人开发者** | 独立工作，资源有限 | 简单、自动化 |
| **小团队（2-10 人）** | 协作工作，资源有限 | 标准化、可追溯 |
| **开源维护者** | 维护开源项目，资源有限 | 统一、可审计 |
| **自托管服务维护者** | 维护自己的服务，资源有限 | 安全、可控 |

### 职责

| 职责领域 | 具体内容 |
|----------|----------|
| **正确使用** | 按照文档使用，不滥用 |
| **反馈问题** | 报告 bug、提出建议 |
| **遵守边界** | 不用于非目标场景 |
| **安全意识** | 保护 secrets、遵守安全规范 |

### 权限

| 权限 | 说明 |
|------|------|
| **使用工具** | 使用 AgentPlane CLI |
| **Fork 仓库** | 可以 fork 后定制 |
| **反馈问题** | 可以报告 bug、提出建议 |

## AI Agent

### 职责

| 职责领域 | 具体内容 |
|----------|----------|
| **意图理解** | 理解用户意图，选择合适的 Skill |
| **命令调用** | 通过 Skill 调用 CLI 命令 |
| **结果验证** | 验证执行结果，处理异常 |
| **安全遵守** | 遵守安全护栏，不越权操作 |

### 权限

| 权限 | 说明 |
|------|------|
| **Skill 调用** | 通过 Skill 调用 CLI |
| **状态查询** | 查询项目状态 |
| **执行操作** | 在人类确认后执行操作 |

### 约束

| 约束 | 说明 |
|------|------|
| **人类在环** | 关键决策需要人类确认 |
| **安全护栏** | 必须遵守安全规则 |
| **审计追踪** | 所有操作有记录 |

## 角色转换

### 贡献者 → 维护者

**条件**：
- 持续贡献高质量代码
- 熟悉项目架构和设计原则
- 获得现有维护者信任
- 愿意承担维护者职责

**流程**：
1. 现有维护者提名
2. 社区讨论
3. 正式授予维护者权限

### 用户 → 贡献者

**条件**：
- 使用 AgentPlane 并发现问题
- 愿意贡献代码或文档
- 遵循贡献指南

**流程**：
1. Fork 仓库
2. 提交 PR
3. 获得贡献者身份
