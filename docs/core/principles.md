# 哲学与工程原则

> 结论：AgentPlane 的原则分三层——道（哲学基座）、法（方法论）、术（工程原则）。道指导法，法指导术，遇到冲突时优先遵循更高层。

---

## 道法术三层关系

道法术是中国传统哲学的三层思维框架：

| 层 | 含义 | 在 AgentPlane 中 |
|----|------|------------------|
| **道** | 基本规律，指导一切的根本原则 | 如何认识世界、如何看待事物 |
| **法** | 应用方式，把道转化为可操作的方法 | 如何思考问题、如何做决策 |
| **术** | 具体技术，把法转化为可执行的代码 | 如何写代码、如何设计系统 |

```
┌─────────────────────────────────────────┐
│           术（工程原则）                  │
│   如何写代码、如何设计系统               │
├─────────────────────────────────────────┤
│           法（方法论）                    │
│   如何思考问题、如何做决策               │
├─────────────────────────────────────────┤
│           道（哲学基座）                  │
│   如何认识世界、如何看待事物             │
└─────────────────────────────────────────┘
```

**冲突时的优先级**：道 > 法 > 术。例如，"奥卡姆剃刀"（法）说如无必要勿增实体，但如果事实证明必须加功能（道：实事求是），就应该加。

---

## 道（哲学基座）

| 原则 | 核心要义 | 在 AgentPlane 中的应用 |
|------|----------|------------------------|
| **实事求是** | 从客观存在的实际事物出发，不凭想象设计功能 | 先看用户真正需要什么，再决定做什么 |
| **矛盾分析法** | 识别并抓住主要矛盾，集中力量解决 | 遇到多个问题时，先解决最关键的 |

**示例**：当同时面对"文档不完整"和"CLI 有 bug"两个问题时，矛盾分析法告诉我们先修 bug——因为 bug 阻塞用户使用，文档只是降低体验。

---

## 法（方法论）

| 原则 | 核心要义 | 在 AgentPlane 中的应用 |
|------|----------|------------------------|
| **调查研究** | 先调查再发言，不猜测；通过实践验证 | 做判断前先读代码、查文档、跑测试 |
| **多源验证** | 收集多方意见，系统化后返回验证 | 设计方案时参考业界实践、用户反馈、技术文档 |
| **集中兵力** | 聚焦核心，不分散精力 | 一个阶段只解决一个主要问题 |
| **奥卡姆剃刀** | 如无必要，勿增实体 | 能不加的功能就不加，保持简单 |

**示例**：设计 CLI 时，"调查研究"要求先看用户怎么用现有工具（读代码、看 issue），而不是凭想象设计命令格式。

---

## 术（工程原则）

### 设计原则

| 原则 | 核心要义 | 在 AgentPlane 中的应用 |
|------|----------|------------------------|
| **CLI-first** | 所有操作通过统一命令行入口 | 所有正式操作必须从 `agentplane ...` 进入 |
| **Agent-first** | AI 可以直接使用，不需要人写脚本 | Skill 路由到 CLI，AI 说人话就行 |
| **证据优先** | 所有操作必须有记录 | 执行后必须验证并记录，出问题可以查 |
| **投影模型** | 从真源派生只读视图；不同职责的代码分开 | Host Inventory → Object Ledgers → App Summaries |
| **执行闭环** | 每个操作都有完整流程 | Plan → Apply → Verify → Record |

### 编码原则

| 原则 | 核心要义 | 说明 |
|------|----------|------|
| **YAGNI** | 不要过度设计 | 只实现当前需要的功能，不为未来可能的需求写代码 |
| **DRY** | 消除重复代码 | 相同逻辑只写一次，通过函数、模块复用 |
| **KISS** | 保持简单 | 能用简单方案解决的，不用复杂方案 |

**示例**："执行闭环"在部署中的体现：Plan（预览变更）→ Apply（执行部署）→ Verify（验证健康）→ Record（写入 Ledger）。不等问题积累，部署完立即验证。
